# AI-Helper

Локальный прототип для подготовки черновиков карточек контрольно-измерительных приборов. Сервис принимает JSON, отправляет данные в DeepSeek и возвращает JSON с SEO-текстом, поисковыми запросами, исходными характеристиками и предупреждениями. Страница на `/` принимает данные через форму или JSON, показывает данные, отправленные модели, и позволяет скопировать результат как JSON, Markdown или текст. Черновик обязательно проверяет контент-менеджер.

## Запуск

Нужны Python 3.11+ и ключ [DeepSeek API](https://platform.deepseek.com/). Для macOS / Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Укажите DEEPSEEK_API_KEY в .env.
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000/ или документацию API http://127.0.0.1:8000/docs. Приложение автоматически загружает `.env` из корня проекта; переменные, уже заданные в окружении, имеют приоритет. Для применения изменений перезапустите сервис. Compose также читает `.env`. Не публикуйте ключ.

Альтернатива с Docker Compose: создайте `.env` из `.env.example`, заполните ключ и выполните `docker compose up --build`. Остановка: `docker compose down`. Порт публикуется только на localhost; `AI_HELPER_PORT` меняет порт хоста.

## API

```bash
curl -X POST http://127.0.0.1:8000/generate \
  -H 'Content-Type: application/json' \
  -d '{"name":"Манометр показывающий DM 02","manufacturer":"Манотомь","specs":{"диапазон измерений":"0–1,6 МПа","класс точности":"1,5"},"description":"Прибор предназначен для измерения избыточного давления."}'
```

Название и производитель обязательны; `specs` — объект строковых значений, `description` — строка. Поля `specs` и `description` можно опустить. Пустые значения характеристик обозначаются «данных нет»; при пустом списке характеристик и отсутствующем описании сервис сообщает об этом в `missing_fields`. Названия нужных характеристик зависят от типа прибора и должны быть указаны пользователем: универсального списка сервис не придумывает. Некорректный JSON и данные возвращают 422, отсутствие ключа — 503, ошибка провайдера — 502, тайм-аут — 504. `GET /health` проверяет только процесс.

Результат содержит `model_input` (проверенный JSON товара, отправленный модели), `seo_title`, `seo_description`, `search_queries`, `commercial_block`, `specs`, `missing_fields`, `warnings` и статус `warning`. Проверки сообщают о заголовке свыше 70 символов, описании вне 800–1200 символов, неверном числе или повторе запросов и числах, которых нет во входе. Это предупреждения для ручной проверки, а не гарантия исправности текста. При недостатке фактов короткий текст предпочтительнее выдумок.

## Поиск при нехватке данных

На странице можно включить «Найти сведения о назначении в интернете». Сервис отправляет название и производителя в [DeepSeek Search API](https://api-docs.deepseek.com/guides/search/) с тем же ключом; поиск оплачивается отдельно по тарифам провайдера. API: добавьте `?web_search=true` к запросу `/generate`. В ответе появятся `search_status` и `sources` с названиями, ссылками и выдержками. Найденные выдержки также видны в `model_input` и передаются модели как непроверенные данные. Проверяйте оригинальные страницы, точное исполнение и каждый факт; поиск может вернуть нерелевантные или устаревшие сведения. При отсутствии результатов или ошибке поиска генерация продолжается по входу с предупреждением.

Характеристики в `specs` всегда берутся только из входа. Фразы с числами, которых нет во входе, исключаются и перечисляются в предупреждениях. Это лишь эвристика: она может убрать правильную фразу и не проверяет другие неподтверждённые утверждения. Перед публикацией нужна проверка редактора.

## Промпт и решения

Системный промпт в `app/main.py` задаёт роль технического редактора, ограничивает текст входными данными, запрещает выполнять инструкции внутри данных и требует JSON. Данные передаются отдельным сообщением. Модель отвечает только за текст; словарь характеристик формируется программно из входа, а не из ответа модели. Ответ модели проходит проверку структуры. Ошибки провайдера не показывают ключ или тело ответа. API использует [JSON Output DeepSeek](https://api-docs.deepseek.com/guides/json_mode/).

## Примеры и проверка

В `examples/` сохранены входные данные и реальные ответы DeepSeek для двух предложений из [фида СОЮЗ-ПРИБОР](https://www.souz-pribor.ru/yml/any/feed.xml), скачанного 3 ноября 2026 года:

- [RGK CT-12 — вход](examples/rgk_ct12.input.json) и [ответ](examples/rgk_ct12.live.json). Название и производитель взяты из offer 194299; характеристики и описание дополнены по [странице выбранного комплекта](https://www.souz-pribor.ru/product/termometr-rgk-ct-12-s-zondom-temperatury-vozdukha-tr-10a-poverkhnostnym-zondom-tr-10s-i-pogruzhnym-z/). Запрос выполнен 4 ноября 2026 года.
- [ОВЕН ПМ01-24.АВ — вход](examples/oven_pm01.input.json) и [ответ](examples/oven_pm01.live.json). Из offer 54084 доступны название, тип и производитель; технические характеристики отсутствуют. Запрос выполнен 3 ноября 2026 года. В группе фида есть и другое исполнение ПМ01-220.АВ.

В фиде нет технических характеристик в отдельных параметрах: `param` содержит только артикул и код товара. Для RGK они добавлены из страницы продавца, а не из фида, и требуют сверки с паспортом. Модель сохранила девять входных характеристик и заполнила commercial-блок. При ручной проверке выявлено, что упоминание «жидких сред» не подтверждено явно входным текстом; сокращённая запись диапазонов тоже требует уточнения. Ответ сохранён без исправлений как пример необходимости проверки редактором. Для ПМ01 характеристики и commercial-блок отсутствуют. Описания RGK и ПМ01 содержат 151 и 108 символов соответственно, то есть не достигают цели 800–1200; сервис указал это в предупреждениях. Оба заголовка укладываются в 70 символов, в каждом ответе по пять запросов. Пара примеров не доказывает общее качество модели.

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check app tests
```

Тесты проверяют API, ошибки, сохранение характеристик, предупреждения и обработку записанных примеров с заменённым провайдером; при запуске тестов сетевой запрос к LLM не выполняется.

## Ограничения

- LLM может сформулировать неподтверждённый факт даже при строгом промпте. Поиск новых чисел — эвристика; он не проверяет смысл, единицы или достоверность паспорта. Достоверность текста и вариантов исполнения проверяет человек.
- Исходные данные отправляются стороннему API. Не передавайте документы, которые нельзя раскрывать провайдеру.
- При ошибке провайдера сервис сообщает об ошибке; автоматических повторов нет. Веб-страница предназначена для локального использования и не содержит авторизации.
- Интеграция с CMS, база данных и массовая обработка не входят в MVP. Дальнейшие улучшения: проверка по паспортам, категориям и конкретным исполнениям, расширение набора реальных примеров, оценка качества модели и экспорт Markdown.
